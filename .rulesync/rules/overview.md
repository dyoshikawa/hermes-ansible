# Project Overview

`hermes-ansible` is an Ansible playbook that installs [Hermes Agent](https://github.com/NousResearch/hermes-agent)
on an Ubuntu LTS VPS (24.04 / 26.04) and runs its messaging gateway as a systemd system service.
Everything lives in one role, `roles/hermes_agent`; `site.yml` applies it to the `hermes` inventory group.

- The role drives the **official installer** (`scripts/install.sh` from the hermes-agent repo) as an
  unprivileged service account (`hermes` by default) with `--skip-setup` and, for a headless VPS,
  `--skip-browser --skip-computer-use`. Do not reimplement what the installer does (uv, Python,
  Node.js, the venv); add flags through `hermes_agent_installer_extra_args` instead.
- Secrets go to `~/.hermes/.env` from `hermes_agent_env` (Ansible Vault in real inventories);
  non-secret settings are merged recursively into `~/.hermes/config.yaml` from `hermes_agent_config`.
  The installer seeds both files, so the role edits them (lineinfile / combine) rather than templating
  them wholesale unless `hermes_agent_env_exclusive` is set.
- The gateway unit content (ExecStart launcher, PATH, KillMode, Restart, HERMES_HOME) is owned by
  Hermes, not by this role: `tasks/gateway.yml` has Hermes render it as the service account (never
  as root), refuses a unit whose shape does not match what Hermes emits, then installs it as root
  with a root-owned drop-in pinning `User=`/`Group=` and enables lingering for the account.
- Every task must be idempotent: CI runs the playbook twice on `ubuntu-24.04` and `ubuntu-26.04`
  runners and fails when the second run reports changes. Prefer `stat` + `when` or
  `changed_when` over `command` tasks that always report changed.
- Variables are prefixed `hermes_agent_`; document new ones in `roles/hermes_agent/defaults/main.yml`
  and `README.md`.
- Tooling is managed with @mise.toml and uv (`mise run install`). `mise run check` runs everything CI
  runs: yamllint, ansible-lint (production profile), the syntax check, gitleaks, actionlint and pinact.
- The repository is **public**. Never commit real hostnames, inventories, vault files or tokens; only
  `*.example.yml` inventories are tracked, and CI must never print `.env` contents.
- AI tool configurations (`AGENTS.md`, `CLAUDE.md`, `.claude/`, `.github/instructions/`, …) are
  generated by [rulesync](https://github.com/dyoshikawa/rulesync) from `.rulesync/`. Never edit the
  generated files directly — edit `.rulesync/**` and run `rulesync generate`.
- When doing `git commit`:
  - Run `mise run check` before committing.
  - Never use here documents in the commit command and never use `--no-verify`.
- GitHub Actions must always be pinned to full-length commit SHAs. Run `mise run pinact` to pin them
  and `mise run pinact:check` to verify.
